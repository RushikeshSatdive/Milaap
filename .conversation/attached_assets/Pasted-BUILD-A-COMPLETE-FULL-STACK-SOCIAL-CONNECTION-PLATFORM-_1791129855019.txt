BUILD A COMPLETE FULL-STACK SOCIAL CONNECTION PLATFORM — MILAAP

Act as a senior full-stack developer, UI/UX designer, product manager, and software architect. Build a complete, responsive, functional web application called Milaap — Reconnect With Your Own People.

Do not create only a landing page, static design, or non-functional prototype. Build the entire application, including frontend, backend, database, authentication, user profiles, matching algorithms, activities, messaging, community features, notifications, and administrative controls.

The application should be suitable for a college social innovation project and demonstrate a realistic, implementable solution to the problem of social division and disconnection within communities.

1. PRODUCT VISION

Product name: Milaap

Tagline: Small Connections. Real Belonging.

Core mission: Reduce social divides by helping people connect with neighbours, students, colleagues, senior citizens, and other community members they would not ordinarily interact with.

People increasingly interact digitally but often remain disconnected from the people around them. Milaap creates meaningful opportunities for real-world interaction through shared interests, complementary skills, short activities, and collaborative community projects.

The platform should not behave like a dating app or conventional social network. Its primary objective is meaningful offline interaction.

The main product experience should follow:

Discover → Match → Plan → Meet → Reflect → Reconnect

2. TECHNOLOGY STACK

Use a modern, maintainable full-stack architecture.

Preferred stack:

* Frontend: React with TypeScript.
* Styling: Tailwind CSS and reusable UI components.
* Backend: Node.js with Express, or Replit’s recommended full-stack architecture.
* Database: PostgreSQL using Replit’s available database integration.
* Authentication: Secure email/password authentication with hashed passwords and persistent sessions.
* Validation: Zod or an equivalent validation library.
* Icons: Lucide React.
* Forms: React Hook Form or an equivalent.
* Deployment: Compatible with Replit deployment.

Use the currently supported Replit integrations and package versions. If a preferred library is unavailable, choose a compatible alternative without compromising functionality.

Keep database credentials, session secrets, and API keys in environment variables. Never expose secrets in client-side code.

Build real database-backed features wherever applicable. Do not substitute localStorage or hardcoded arrays for core persistent application data.

If an external integration requires credentials, implement a graceful fallback and explain the required configuration.

8. PEOPLE DISCOVERY AND CONNECTION MATCHING

This is one of the core features.

Create a Discover page with searchable, filterable member cards.

Each card may display:

* Display name.
* Profile picture or initials.
* Short introduction.
* Shared interests.
* Skills offered.
* Skills sought.
* Community affiliation.
* Broad locality, if the user permits it.
* Availability and preferred activities.

Do not reveal exact residential addresses, phone numbers, or sensitive personal information.

Filters:

* Shared interests.
* Skills offered.
* Skills wanted.
* Community.
* Preferred activity.
* Availability.
* Group activities versus one-to-one activities.

Implement a transparent matching algorithm.

Suggested initial scoring:

* Complementary skill match: 35 points.
* Shared interests: 25 points.
* Preferred activity compatibility: 15 points.
* Availability compatibility: 15 points.
* Shared community membership: 10 points.

Normalise scores appropriately and return a score from 0 to 100.

Avoid ranking users based on sensitive characteristics.

Explain each match with a simple reason, such as:
“You can teach smartphone photography, and Priya wants to learn it.”

Provide actions:

* View profile.
* Send connection request.
* Save for later.
* Suggest an activity.
* Dismiss suggestion.

Prevent duplicate requests and self-matching. Handle accepted, pending, rejected, cancelled, and blocked states.

Allow users to dismiss or refresh recommendations without manipulating other users’ profiles.
